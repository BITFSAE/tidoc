# Tidoc 简介

Tidoc 是整理报账发票与支撑材料的桌面软件，支持 Windows 和 macOS。一张发票对应一个条目，发票、付款截图、实物照片和查验单都放在这个条目里，核对后按批次导出或打印。

识别、数据存储和材料管理都在本机完成，Tidoc 不会自动上传发票和材料。

![Tidoc 主界面](/images/main-overview.png)

## 解决什么问题

报账材料常分散在聊天记录、下载目录和相册里；发票信息靠手工录入，缺的材料往往临近提交才发现，多人报账还要来回传文件。

Tidoc 把这些事放在同一个界面里：

- **整理**：一张发票对应一个条目，付款截图、实物照片、查验单与备注都放在条目里。
- **核对**：集中查看缺少的材料、需要核对的识别结果和实付金额差异。
- **协作**：把选中的条目连同材料导出为 `.tidoc` 绑定包，交给他人继续整理。
- **输出**：生成总览 Excel、附件整理包、材料 PDF，以及报账方案规定的 Word 文档。

个人、团队和学生社团都可以使用，一台电脑也可以代多人整理。

## 发票是怎么识别的

导入发票后，Tidoc 读出发票号码、开票日期、销售方、购买方、价税合计和物资明细，再检查读出的结果是否自洽。这一步在本机完成，不需要联网。

### 1. 有 XML 就读取 XML

数电发票的 XML 文件按固定的字段存放数据。Tidoc 直接读取这些字段，并与同一张发票的 PDF 配对。能拿到 XML 时，建议和 PDF 一起导入。

### 2. 没有 XML 就读取 PDF 里的文字

数电发票的 PDF 带有可以复制的文字，Tidoc 读取这些文字。

不同开票平台的版式有差异，Tidoc 会处理常见的排版问题，例如购买方与销售方左右分栏、长品名折行、明细行后面的折扣行，处理方式见[核对识别结果](/guide/check#tidoc-怎么读取发票)。读取时按文字顺序和页面位置分别计算明细，明细金额相加等于价税合计的结果才会采用。

### 3. 用金额核对结果

读出文字后做两项核对：

- 明细金额相加，应该等于价税合计。
- 购买方抬头应在已设置的抬头范围内，购买方税号应与抬头对应。

核对不通过时，条目会出现「识别提醒」，写明原因，例如「明细识别合计与发票总额相差 12.00」。提醒不影响继续整理。你可以在详情里修改字段，或者用「重新识别」刷新结果。

### 4. 读不出来怎么办

扫描件和手机拍的发票照片没有文字，本地识别读不到字段。可以在详情里手动填写，也可以用[阿里云 OCR](/guide/aliyun-ocr) 补齐。核对步骤见[核对识别结果](/guide/check)。

## 数据与联网

- 识别、数据和材料都在本机。联网的操作只有少数几类，例如在线查验、云识别和检查更新，完整列表见[设置与数据](/guide/settings#本机数据与联网)。
- 核心程序不含打印和 OCR 的组件，需要时在软件里安装。
- 阿里云 OCR 默认不需要安装。维护者用同一批发票对比过本地识别和阿里云 OCR，在报账使用上本地识别可以替代阿里云 OCR，部分发票上结果更好。云识别保留为可选的补充，用来补齐明细或提供第二份核对结果。

## 目前的限制

- 主要面向数电发票。其他版式可能读不全，需要手动补充，识别提醒会标出。
- 付款截图 AI 识别是实验性功能，默认关闭。使用时需要在「设置 → 开发者选项」填入服务商的 Key，截图会上传到所选服务商并按量计费，结果只供参考，见[设置与数据](/guide/settings#付款截图-ai-识别)。
- 打印和 Word 输出需要先安装「打印导出组件」，阿里云 OCR 需要先安装「OCR 识别组件」。两者都在「设置 → 组件与更新」里安装。

# 核对识别结果

发票录入时，Tidoc 本地解析引擎会自动提取关键字段并执行一致性校验。本页说明如何利用状态视图组织核对流程、排查处理「识别提醒」，以及触发重新识别。

## 状态视图分流核验

主界面顶部的状态视图根据条目的齐备度与校验结果动态归类：

- 「全部」：当前筛选范围内的全量条目。
- 「待补材料」：尚未补齐方案要求必需材料的条目。
- 「识别提醒」：解析字段自校验未通过、需要人工复核的条目。
- 「已识别」：已完成阿里云 OCR 并保存云端结果的条目。
- 「OCR 待确认」：本地结果与云识别结果存在差异、等待人工决策的条目。
- 「已修改」：实付金额与发票票面金额不一致的条目。
- 「齐备」：必需材料已补齐且无「严重问题」的合规条目。

「已识别」与「OCR 待确认」仅在安装「OCR 识别组件」后显示，详见[阿里云 OCR](/guide/aliyun-ocr)。

![状态视图和筛选工具条](/images/status-views.png)

推荐的核对流转顺序：优先切换至「待补材料」视图补全支撑材料；再切换至「识别提醒」视图核验异常字段；两者均处理完毕后，条目自动归入「齐备」视图。卡片标注「识别提醒」或更严重的「严重问题」徽标，鼠标悬停可直接查看详细原因。

## 本地发票解析逻辑

识别过程在本机离线完成，自动提取发票号码、开票日期、销方名称、购买方抬头、价税合计与物资明细：

- **含 XML 文件**：直接解析标准结构化字段，数据精准度最高。
- **仅 PDF 文件**：提取数电发票 PDF 文本图层中的文字流，针对分栏排版、长文本折行及折扣行进行重构分词；纸质扫描件因无文字层无法直接解析。
- **字段缺漏处理**：未成功解析的字段留空，条目卡片将标注「无发票号」或「未识别销售方」，需在详情中人工补录。

## 识别提醒排查与订正

条目出现「识别提醒」的典型原因：

- 未能提取到物品明细清单。
- 明细行金额累计合计与发票价税合计不一致（可能明细识别不全，应以票面价税合计为准）。
- 购买方抬头为空，或识别到的抬头未落在当前方案配置的抬头清单内。
- 方案已为该抬头配置税号，但发票未识别到税号，或识别税号与配置不符。
- 开启付款截图金额识别后，截图未能提取到数字，或截图金额与发票金额不符。

订正步骤：

1. 进入「识别提醒」视图，或将鼠标悬停在卡片徽标上查看具体错误摘要。
2. 点击卡片或按 `Enter` 进入条目详情，「关键信息」下方将列出详细提醒说明。
3. 对照发票票面原件核实：点击「关键信息」中的数值可直接编辑，按回车保存；在「物品明细」中可点击单元格订正，或点击「＋ 添加明细行」补录遗漏品项。

![带识别提醒的条目详情](/images/warning-detail.png)

所有人工修改均自动记录在详情底部的「修改记录」中。一般的「识别提醒」仅提示数据一致性存疑，不阻断材料齐备；但「严重问题」（如发票票面购买方与条目所选抬头明确冲突）将直接导致条目无法判定为齐备。

## 重新识别

当软件版本升级更新了解析规则，或替换了发票源文件与付款截图后，可批量刷新解析数据：

1. 选中需要重新处理的条目（多选方式见[筛选、标签与批次](/guide/organize)）。
2. 点击批量操作工具条中的「重新识别」。
3. 在「重新识别」窗口中按需勾选「发票」与「付款截图」；若未启用截图金额识别，「付款截图」项不可选。
4. 点击「开始识别」；系统将跳过文件哈希未变且已按最新规则处理的条目，仅对未完成或变更的文件进行重析。

软件升级后，建议在「识别提醒」视图中按 `Cmd/Ctrl + A` 全选条目，批量触发「重新识别」以应用最新的版式兼容算法。

## 阿里云识别比对

对于配置了阿里云 OCR 的场景，点击批量「云识别」后，条目详情将展现「阿里云识别」双栏对照区：

- 若本地提取字段为空，部分字段可自动由云识别结果补充。
- 若物资明细项存在差异，条目自动标为「OCR 待确认」。
- 在详情中支持逐个字段点击「采用」，或点击「采用阿里云明细」覆盖本地提取结果。

开通流程与计费详情见[阿里云 OCR](/guide/aliyun-ocr)。

## 遇到识别异常的发票？

数电发票和各种开票平台的版式层出不穷。如果你手头有本地读取不全、明细顺序错乱或金额核算不符的发票：

- 欢迎将脱敏后的发票原文件（PDF 或 XML）发送至邮箱 `info@bitfsae.com`。
- 也可以在 [GitHub 提交 Issue](https://github.com/BITFSAE/tidoc/issues) 并附上异常现象描述。

我们会将新的版式样本加入自动化回归测试集，并在后续版本中持续优化解析规则。

# Tidoc 简介

Tidoc 是一款用于整理报账发票与支撑材料的桌面工具，支持 Windows 和 macOS。软件以一张发票对应一个条目，将发票、付款截图、实物照片与查验单集中管理，核对无误后按批次导出或打印。

发票识别、数据存储与附件管理均在本机完成，发票文件不会上传。

![Tidoc 主界面](/images/main-overview.png)

## 解决什么问题

报账材料常分散在聊天记录、下载目录和相册中；发票信息多靠手工录入，缺漏材料往往临近提交才被发现，多人报账还需频繁往复传递文件。

Tidoc 将发票与关联材料归拢到统一工作台：

- **整理**：一张发票对应一个条目，付款截图、实物照片、查验单与备注集中归整。
- **核对**：直观展示缺漏材料、识别异常提醒与实付金额差额。
- **协作**：可将所选条目连同附件导出为 `.tidoc` 绑定包，交接给他人继续整理。
- **输出**：生成总览 Excel、规范命名附件包、材料拼接 PDF，以及报账方案要求的 Word 文档。

适用于个人报账、团队报账及学生社团，单台电脑亦可代多人分类归整。

## 发票识别机制

发票识别是 Tidoc 的核心基础。导入发票后，软件直接在本机解析发票号码、开票日期、销售方、购买方、价税合计与物资明细，并自校验数据一致性。全程在本机完成，无需网络请求。

### 1. 优先读取 XML 结构化数据

数电发票开票平台生成的 XML 文件具有规范的字段结构。Tidoc 直接解析字段，并与对应 PDF 票面自动配对。若能获取 XML，建议优先提供。

### 2. 无 XML 时解析 PDF 文本图层

数电发票 PDF 内置文本图层。Tidoc 直接提取页面文本流，无需图像 OCR 认字，解析迅速且完全离线。

针对不同开票平台的版式差异，Tidoc 对常见排版异常进行了适配整理：
- 购买方与销售方左右分栏识别
- 长文本名称折行拼接
- 明细行与后续折扣行自动关联
- 数量、单价与金额粘连分词

系统按文本流与页面几何位置分别核算，当明细金额累加值与价税合计完全一致时方予采纳。

### 3. 金额与抬头自校验

文本提取后自动执行两项交叉校验：

- 物资明细金额相加，必须等于价税合计。
- 购买方抬头须匹配方案配置的抬头，税号须与对应抬头一致。

校验未通过时，条目将显示「识别提醒」并说明具体偏差（例如「明细识别合计与发票总额相差 12.00」）。提醒不会阻断后续整理，也不会被静默忽略；可在详情中人工订正，或点击「重新识别」刷新结果。

### 4. 扫描件与拍照件处理

纸质发票扫描件或手机翻拍图不含文本图层，本地识别无法直接提取字段。可在条目详情中手动录入，或调用[阿里云 OCR](/guide/aliyun-ocr) 补充识别。具体操作见[核对识别结果](/guide/check)。

## 产品特点

- **本地离线**：识别、数据与附件均存放于本机。仅在线查验发票、检查/下载更新、调用阿里云 OCR、打开外部链接时产生网络请求。
- **极速解析**：导入后由本地引擎即时解析，无需等待网络上传返回；支持按目录整批载入。
- **轻量按需**：核心安装包不捆绑打印渲染与云 OCR 组件，按需在设置中一键加载。
- **严谨核验**：逐张发票核对金额与明细自洽性，异常项明确标注提醒。已沉淀两百余张真实发票回归测试，遇到新版式持续扩充样本。若遇到本地识别不准的发票，欢迎将脱敏样本发送至邮箱 `info@bitfsae.com`。
- **云识别定位**：在常规报账场景中，本地文本解析已能满足绝大多数识别需求，且部分发票效果更好。阿里云 OCR 仅作为可选付费补充，用于扫描件补录或第二通道比对。
- **跨平台支持**：提供 Windows 与 macOS 原生安装包。
- **多维管理**：支持状态视图、标签、批次、多维筛选与批量操作，清晰把控各阶段报账进度。
- **交接协作**：支持打包导出 `.tidoc` 绑定包进行整包交接；单台设备亦支持多报账人分别归整。

## 当前限制

- 优先适配数电发票。其他发票版式若字段识别不全，需在详情中手动补充，系统会以识别提醒告知。
- 付款截图金额识别为实验性功能，默认关闭；调用系统自带的文字识别能力提取金额，结果供参考，建议以截图实际数字为准。
- 打印导出 Word 与材料 PDF 需安装「打印导出组件」，阿里云 OCR 需安装「OCR 识别组件」；均可在「设置 → 组件与更新」中按需安装。

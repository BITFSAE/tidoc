# Tidoc 使用指南

Tidoc 用于整理报账发票和相关材料。它以一张发票为一个条目，把发票、付款截图、实物图、查验单、实付金额和备注放在一起，再按报账批次导出或打印。

第一次使用时，建议先完成“快速入门”。遇到具体问题时，可按目录直接查找。

## 一、先了解几个概念

### 条目

一张发票对应一个条目，也就是主界面中的一张卡片。发票内容、材料、实付金额、备注、标签和识别结果都保存在这个条目中。

### 材料

材料是报账时需要随发票一起提交的文件和信息：

- 发票 PDF：保留原票，供查看和打印票面。
- 发票 XML：提供结构化发票数据，可以先导入，再补对应 PDF。
- 付款截图：记录实际付款情况，可识别截图中的金额。
- 实物图：记录采购物品的照片，可在设置中设为必需。
- 查验单：国家税务总局查验平台生成的 PDF。
- 自定义材料：方案要求的合同、审批单或其他文件。
- 实付金额：实际支付金额，可以等于发票金额，也可以单独填写。

### 报账人

报账人表示发票归属，姓名必填。审核人是否需要填写、是否放在高级选项，由报账方案决定。团队中有多人报账时，可以为每个人建立一个报账人。

### 收款信息

收款信息用于方案中需要收款段落的文档，包含姓名、人员编号、联系方式、账户类型、开户行和账号。它与报账人是两组独立信息。人员编号可由方案显示为学号或工号，BITFSAE 使用学号；填写时保留前导零。

### 标签

标签用于分类和筛选，例如“电控”“比赛物资”“待确认用途”。一个条目可以有多个标签。

### 报账批次

报账批次用于组织准备一起提交、导出或打印的条目。批次可以填写备注，提交完成后可以归档。

### `.tidoc` 绑定包

绑定包用于在不同电脑或不同人员之间交接材料。它包含条目、附件、报账人和完整性校验信息。导入前会显示预览，便于确认报账人、审核人、标签和批次。

### 识别提醒和材料齐备

这两个状态分别表示不同内容：

- 识别提醒：发票内容需要核对，例如金额、明细、抬头或购买方税号存在异常。
- 材料齐备：当前材料要求已经满足。

一个条目可能材料已经齐备，同时仍有识别提醒。完成报账整理时需要同时查看这两类状态。

## 二、下载和安装

### 下载地址

- [Tidoc 官网入口](https://www.bitfsae.com/)：首页底部选择「报账软件」。
- [GitHub Releases](https://github.com/totok22/tidoc/releases/latest)：可查看和下载各版本安装包。

### Windows

下载 `tidoc-core-windows-v{version}.exe`，双击后按提示安装。程序默认安装到当前用户目录，安装过程通常无需管理员权限。

安装完成后，开始菜单会出现 Tidoc。安装器也会为 `.tidoc` 绑定包配置文件图标和打开方式。

如果 Edge 或 Windows SmartScreen 显示安全提示：

1. 先确认文件来自 Tidoc 官网或 GitHub Releases。
2. Edge 下载栏中选择「保留」或「仍要保留」。
3. SmartScreen 窗口中选择「更多信息 → 仍要运行」。
4. 由单位统一管理的电脑如果限制安装，请联系设备管理员处理。

### macOS

下载 `tidoc-core-macos-v{version}.dmg`，打开后把 Tidoc 拖入“应用程序”。

macOS 首次打开时如果显示来源提示，可在 Finder 中右键 Tidoc，选择「打开」并再次确认。也可以前往「系统设置 → 隐私与安全性」，在安全提示旁选择允许打开。

## 三、快速入门

下面是一套完整的基础流程。

### 第一步：选择方案并创建报账人

首次打开 Tidoc 时，先选择通用、BITFSAE 或导入团队方案，再创建报账人：

1. 姓名填写发票的实际归属人。
2. 方案要求审核人时，填写负责审核或接收材料的人；其他方案允许留空。
3. 有多位报账人时继续添加。添加第二位后，软件会自动开启代填模式，新建和导入时可以选择归属。

报账人可以随时在「设置 → 报账人 → 管理」中修改。

### 第二步：导入发票

点击右上角「导入发票」，选择一张或多张发票 PDF、XML，也可以直接选择包含发票的文件夹。

如果同时有 XML，把 XML 与对应 PDF 放在一起选择。Tidoc 会自动配对，并优先使用 XML 中的结构化数据。

### 第三步：补齐材料

在发票卡片上添加付款截图、实物图和查验单，确认实付金额。材料也可以拖到卡片上，或在条目详情中集中添加。

### 第四步：核对条目

依次查看「待补材料」「识别提醒」「OCR 待确认」视图。打开详情后核对发票字段、明细、材料和备注。处理完成的条目会进入「齐备」。

### 第五步：整理和交付

勾选需要一起提交的条目，建立报账批次。材料准备完成后，根据交付方式选择：

- 导出 `.tidoc` 绑定包，交给其他人继续整理。
- 导出总览 Excel 或附件整理包。
- 使用打印导出组件生成材料 PDF 和方案定义的 Word 文档。

## 四、导入发票和材料

### 使用「导入发票」

「导入发票」适合一次处理多张发票：

1. 点击右上角「导入发票」。
2. 选择多个文件，或选择整个文件夹。
3. 在预览中检查识别结果，选择报账人和报账批次；也可以就地新建报账人或批次。
4. 确认后创建条目。

批量导入会为 PDF 匹配同组 XML。没有对应 PDF、但能识别发票号码的 XML 也会进入独立导入组；无法识别的 XML 留在未分组列表中，供核对。文件夹中的付款截图和查验单会继续尝试匹配到刚创建的条目；归属明确时自动添加，需要确认时会要求手动选择。

### 拖拽导入

拖拽位置会影响文件用途：

- 拖到主界面空白处：作为一组新文件读取。发票会创建条目，其他材料会尝试匹配现有条目。
- 拖到某张发票卡片：直接把文件添加到该条目。
- 拖到详情中的材料区域：添加到当前条目的对应材料分组。

一次拖入 PDF、XML、付款截图和查验单时，Tidoc 会先识别文件类型，再完成创建和匹配。

### 粘贴导入

先在 Finder 或资源管理器中复制文件，再回到 Tidoc 粘贴：

- 在主界面粘贴发票时，会先打开导入确认框，可选择本次条目的报账人和报账批次；没有合适选项时可在弹窗中直接新建。
- 先打开某个条目详情再粘贴付款截图、实物图或查验单时，材料会直接归入当前条目，并继续执行金额识别、发票归属和齐备状态校验；详情会立即显示处理结果。
- 在主界面粘贴其他材料时，处理方式与拖到主界面空白处相同：能唯一匹配则自动绑定，否则要求选择条目。

### 使用「新建」

「新建」适合处理单张发票。可以上传 PDF、XML 或两者，检查识别字段，再创建条目。

### 导入 XML

单条新建和批量导入都可以先提供 XML，之后再补 PDF。XML 提供发票号码、金额、税额和明细，PDF 保留票面。需要打印票面的输出会在预检中要求 PDF；补齐后重新检查生成内容。

导入到已有批次时，新条目采用该批次保存的默认方案修订，包括默认抬头、实付初值和建议标签。方案后来修改这些默认值，也不会改变批次原来的新建规则。

### 重复发票

Tidoc 会在全库中检查发票号码和发票文件内容。发现已有发票时，会显示原条目的报账人和基本信息，方便定位现有记录。

## 五、补齐和管理材料

### 从卡片添加

卡片上的材料按钮适合快速操作：

- 点击「付款」添加付款截图或填写实付金额。
- 点击「实物」添加一张或多张实物图。
- 点击「查验」进入在线查验流程。
- 点击「详情」查看全部材料和字段。

右键材料按钮可以直接打开已有文件。再次点击材料按钮可以继续添加同类文件。

### 从详情添加

详情页适合集中整理：

1. 展开发票、付款截图、实物图或查验单分组。
2. 添加、替换或删除文件。
3. 为具体附件填写附件备注。
4. 填写条目备注和实际物资名称。
5. 核对实付金额与发票金额。

### 付款截图和实付金额

付款截图金额识别是实验性功能，默认关闭，添加截图后需要自己填写实付金额。使用系统自带 OCR，效果有限，识别结果仅供参考。可在「设置 → 报账方案 → 管理」把「付款截图金额识别」改为本地识别；开启后，添加截图时 Tidoc 会读取截图中的付款金额：

- 识别结果与发票金额一致时，可以直接写入实付金额。
- 多张截图会显示各笔金额和合计。
- 多个条目的金额相同，或截图中有多个候选金额时，软件会让用户选择条目或确认金额。

「实付默认等于发票金额」由方案控制。开启时采用有效发票金额；金额缺失仍留空，零和负数均保留。实际发生分笔付款、部分付款或金额调整时，在卡片或详情中填写真实实付金额。

### 在线查验并归档查验单

1. 点击卡片上的「查验」。
2. Tidoc 打开国家税务总局查验平台，并预填可用的发票信息。
3. 完成验证码和查验。
4. 在官网点击「打印」，通过系统打印窗口选择横向布局并另存为 PDF。
5. 把 PDF 保存到下载、桌面、文档或设置中的额外归档目录。
6. 等待约 1–2 秒，Tidoc 会识别发票号码并归入当前条目。

第一次查验生成的查验单通常包含更完整的查验信息，建议优先保存。已有查验单也可以从卡片或详情手动上传。

### 设置材料要求

打开「设置 → 报账方案 → 管理」，在「材料要求」里可以分别设置以下内容是否计入齐备状态：

- 付款截图
- 实物图
- 查验单
- 实付金额

发票是每个条目的基础材料，PDF 或 XML 可以用于日常整理。其他要求按条目绑定的方案修订判断：通用方案仅默认要求发票，BITFSAE 和外部团队使用各自材料规则。

抬头、材料要求和其他方案设置一起编辑，点「保存更改」后只生成一个新修订。已有条目保留原规则；需要调整时，先查看应用新方案的预览，再确认重绑定。自定义材料的名称、格式和份数要求会在材料区及缺项提示中显示。

## 六、核对识别结果

### 列表视图

主界面的状态视图用于分步骤处理条目：

- 全部：当前范围内的全部条目。
- 待补材料：还需要补充必需材料的条目。
- 识别提醒：发票字段、金额、明细、抬头或税号需要核对的条目。
- 已识别：已经保存阿里云 OCR 结果的条目。
- OCR 待确认：本地结果与阿里云结果存在待确认差异的条目。
- 已修改：实付金额与发票金额存在差异的条目。
- 齐备：材料要求和发票校验均已完成的条目。

严重问题会使用更醒目的状态显示。打开详情可以查看具体原因。

### 发票识别顺序

Tidoc 优先读取 XML；同组没有 XML 时，解析 PDF 文本。常见数电发票的分栏明细、折扣行和错位文本会在解析时整理。

以下情况通常会进入识别提醒：

- 发票号码、日期、销售方或金额缺失。
- 明细金额与价税合计无法闭合。
- 发票抬头超出已配置范围。
- 已配置抬头的购买方税号缺失或不匹配。
- 附件类型或发票归属需要确认。

### 重新识别

识别规则更新，或发票、付款截图被替换后，可以刷新识别结果：

1. 勾选一个或多个条目。
2. 点击批量工具条中的「重新识别」。
3. 选择发票、付款截图或两者。
4. 查看每个条目的处理结果。

已经由当前规则处理且文件内容相同的材料会跳过。这样可以直接对旧条目运行批量操作，把需要更新的部分集中刷新。

### 阿里云结果对比

阿里云 OCR 用于补齐本地遗漏，并提供第二份结果用于核对。云端返回的新内容会按字段显示：

- 本地字段为空时，可自动补齐部分安全字段。
- 本地与云端明细存在差异时，进入「OCR 待确认」。
- 详情页会显示本地值、云端值和采用状态。
- 用户可以逐项采用，也可以保留当前值。

规格型号用于参考；名称、单位、数量、金额和明细行数是主要核对项。

## 七、筛选、标签和批次

### 搜索和筛选

搜索框支持以下内容：

- 发票号码
- 销售方
- 金额
- 条目备注
- 物资名称

工具条可以直接按抬头、报账人和标签筛选。「高级」中还可以组合日期、金额、状态、查验情况、备注和付款截图数量。

状态视图、批次和筛选条件可以叠加。例如，先打开某个批次，再选择「待补材料」和报账人，可以集中处理这个人在该批次中的缺失材料。

### 选择多个条目

- 点击卡片选择条目（也可用方向键移动、空格选中）；选中的卡片整体变色。卡片左侧的彩色边是抬头颜色，悬浮可看到抬头名称。
- 按住 `Shift` 点击可连续选择。
- `Cmd/Ctrl + A` 选择当前列表中的全部条目。
- `Esc` 清除当前选择。

选择后会显示批量操作工具条，可统一修改报账人、添加标签、移动批次、重新识别、导出、打印或删除。

### 使用标签

选中条目后点击标签操作，也可以按 `T`。标签支持批量添加和移除。删除一个标签只会移除分类标记，条目和材料仍会保留。

### 使用报账批次

1. 选中准备一起处理的条目。
2. 点击批次操作并创建新批次，或移动到已有批次。一个条目只归属于一个批次。
3. 点击左侧批次名称查看其中条目。
4. 点击批次右侧「⋯」编辑名称、填写批次备注或归档。

批次备注适合记录本批次的用途、提交要求和交接信息。批次中的单个条目还可以填写催办备注。

批次编辑窗口的「批次报账信息」可填写方案要求的字段、选择本批次收款对象，并设置允许修改的输出选项。混合方案或历史修订分开显示各自字段；固定选项按方案执行。

保存批次收款选择后，再次打开窗口会显示已选对象。更换收款对象时选择完整记录，不会从另一人的资料中补字段。

归档后的批次进入「已归档」工作面。需要继续处理时可以恢复到在办。再次点击当前批次会返回所在工作面的全部条目。删除批次默认保留条目，条目会回到「未进批次」；勾选危险选项后也可同时永久删除批次内条目及附件。

## 八、绑定包、导出和打印

### 导出 `.tidoc` 绑定包

1. 选中需要交接的条目。
2. 点击「导出」。
3. 勾选「绑定包」，填写导出名称。
4. 点击「开始导出」。

绑定包包含条目、附件、报账人和完整性校验信息。阿里云识别结果与“已识别 / 待确认”状态也会一起保存。

「设置 → 偏好」可以控制绑定包是否包含：

- 条目备注
- 附件备注和备注修改记录
- 条目标签

每条资料默认采用自身方案修订的带出设置。混合方案选择时，各条分别处理备注和标签；明确修改导出选项也须符合对应方案的固定要求。

### 导入 `.tidoc` 绑定包

可以通过三种方式进入导入预览：

- 点击主界面顶部的「导入包」。
- 把一个 `.tidoc` 文件拖入或粘贴到 Tidoc。
- 在系统文件管理器中双击 `.tidoc` 文件。

Tidoc 同时只保留一个主窗口。软件已经运行时，再次点击应用图标会回到现有窗口；双击 `.tidoc` 文件会把它交给现有窗口。如果当时正在填写弹窗，导入预览会等当前弹窗关闭后再打开，不会覆盖未完成的输入。

一次处理一个绑定包。预览页面会显示完整性状态和包内条目，并提供以下调整：

- 勾选本次要导入的报账人；当前本机身份与包内身份一致时，会默认只选自己。
- 在条目列表中单独取消不需要导入的条目。
- 修改所选条目的报账人和审核人。
- 给所选条目追加标签。
- 移动到已有批次、创建新批次或暂时留在批次外。
- 个别条目需要去不同批次时，点击「逐条调整」后对该条使用「单独设置」；可覆盖为已有批次、单独新建的批次或「未进批次」。

如果当前有在办批次，预览会默认选择「已有批次」；如果没有，则默认选择「新建批次」，并用绑定包文件名预填批次名称。选择「不加入」时，导入前还会再次确认，避免条目无意中留在「未进批次」。

条目列表会预先标出「新增」「补充」或「已有·无变化」，并显示本机条目当前所在批次。命中已有发票时，Tidoc 保留本机已经填写的非空值，并自动补充包内新增的查验单、付款截图等材料，合并备注和普通标签，补齐本机为空的基础信息、明细和云识别记录；「已报销 / 未报销」和「已支付 / 未支付」会按包内状态替换相反标签，避免状态互相矛盾。包内没有新增内容时才跳过；如果对该条显式设置了目标批次，仍会按选择调整批次。整次导入仍按一个事务处理，失败不会留下半份结果。

### 导出总览和附件

导出窗口还可以生成：

- 总览 Excel：汇总发票字段、金额、报账人、状态和备注。
- 附件整理包：按统一名称整理选中条目的材料并生成清单。

文件保存在导出目录。可以在导出完成窗口或「设置 → 数据位置」中打开该目录。

### 安装打印导出组件

第一次点击「打印」时，如果组件尚未安装，按弹窗提示安装。也可以前往「设置 → 组件与更新 → 软件与组件 → 管理」安装或修复。

### 生成打印件

1. 选中需要打印的条目。
2. 点击「打印」。
3. 选择合并方式和需要生成的 Word 文档。
4. 填写相关字段，需要时展开「本次输出设置」调整每项输出的金额口径、排序或 PDF 选项。
5. 点击「检查生成内容」，查看分组、预计文件和缺项；通过后点击「生成选中内容」。

输出的默认选项、材料范围、图片布局和顺序由方案决定。BITFSAE 默认按条目排列发票、付款截图和查验单，其他方案可采用不同安排。预检会列出预计文件、分组和缺项，Word 与材料 PDF 按主体分别生成。

未配置默认输出时，窗口采用方案声明的默认选择；明确保存“全不选”会保留空选择。本次取消全部勾选后，也不会自动重新选中。生成前至少选择一项需要的输出。

修改输出选择、日期或字段后，需要重新检查生成内容；旧预览会失效。关闭窗口后，尚未返回的旧预览也不会恢复到界面中。

生成需要收款信息的文档前，在报账方案的「收款信息」入口填写并选择完整收款对象。统一收款选择一个对象；按报账人分别收款时，补齐对应映射。预检显示名称和账号尾号，缺少映射不会自动猜人。无收款段落的输出无需填写账号。

文档名称、数量和模板由方案决定。BITFSAE 包含“报账说明”和“验收单”，其他团队可配置采购申请、费用结算等文档。批次字段和备注按实际所属批次带入。同一修订的本地方案副本也分别填写本次字段。

选中未进批次的条目时，可在“未进批次条目的本次信息”填写所需批次字段。这些值仅用于本次生成并保存到导出记录，不会建立批次或改变条目归属。

通用材料 PDF 可在未安装来源团队包时使用，包含所选条目的内置及自定义材料，并按真实抬头分别生成。XML 不能充当票面；不可转换的文件会在生成前提示，改用附件整理包可保留原件。

生成窗口会依次显示核对原始材料、生成总览和附件包、生成 Word 和材料 PDF、检查生成文件、保存交付文件等实际阶段。有可计数的步骤会显示完成数，文档生成期间显示当前阶段。

生成中可以取消，当前步骤结束或打印进程停止后显示取消结果，不保存半套交付文件。取消或失败后查看原因、调整资料，再重新检查生成内容。当前真实应用与跨平台验收范围见[计划记录](TEAM_ADAPTER_PLAN.md#23-实施与验收覆盖记录)。

### 历史导出

历史任务保存生成时的数据、方案修订和资源摘要。查看原文件不会重算当前资料；按原数据重新生成时，使用原快照。原附件已删除或内容变化时，会提示补齐资源，原文件仍可查看。取消或生成失败的任务不发布半套结果。

如果保存导出记录时失败，先检查数据目录的剩余空间和写入权限。任务仍保留原数据快照和材料，恢复后可按原数据重新生成；原预览会失效，避免继续使用未保存成功的预览。

## 九、使用阿里云 OCR

阿里云 OCR 是可选的付费识别功能。它适合补齐规格、单位、数量等本地解析遗漏，并提供云端结果用于比对。普通导入、材料整理和打印流程可以直接使用本地识别结果。

### 1. 开通 OCR 服务

1. 登录阿里云并完成账号要求的实名认证。
2. 打开[增值税发票识别产品页](https://ai.aliyun.com/ocr/invoice)。
3. 按页面提示开通文字识别 OCR 和增值税发票识别服务。
4. 在[OCR 控制台](https://ocr.console.aliyun.com/overview)确认服务状态。

Tidoc 调用的是阿里云 `RecognizeInvoice` 接口。接口说明见[阿里云 RecognizeInvoice 文档](https://help.aliyun.com/zh/ocr/developer-reference/api-ocr-api-2021-07-07-recognizeinvoice)。

### 2. 创建专用 RAM 用户

为 Tidoc 单独创建一个 RAM 用户，可以把权限限制在 OCR 范围内：

1. 打开[RAM 控制台](https://ram.console.aliyun.com/)，进入「身份管理 → 用户」。
2. 点击「创建用户」，登录名称可填写 `tidoc-ocr`。
3. 创建后进入该用户详情页。
4. 在「权限管理」中新增授权，搜索并选择 `AliyunOCRFullAccess`。

`AliyunOCRFullAccess` 是阿里云提供的 OCR 系统策略，权限范围是文字识别 OCR 产品。可查看[策略说明](https://help.aliyun.com/zh/ram/developer-reference/aliyunocrfullaccess)和[创建 RAM 用户说明](https://help.aliyun.com/zh/ram/user-guide/create-a-ram-user)。

### 3. 创建 AccessKey

1. 在 `tidoc-ocr` 用户详情页打开「凭证管理」。
2. 在 AccessKey 区域点击「创建 AccessKey」。
3. 按页面提示完成安全验证。
4. 保存 AccessKey ID 和 AccessKey Secret。

AccessKey Secret 只在创建时显示一次。建议把它保存在可靠的密码管理工具中。详细步骤见[阿里云 AccessKey 文档](https://help.aliyun.com/zh/ram/user-guide/create-an-accesskey-pair)。

### 4. 在 Tidoc 中配置

1. 打开「设置 → 组件与更新 → 软件与组件 → 管理」。
2. 安装「OCR 识别组件」。
3. 返回设置中的「阿里云 OCR」。
4. 填写 AccessKey ID 和 AccessKey Secret，点击「保存」。

密钥保存后，设置页会显示脱敏后的 AccessKey ID 和本机累计调用次数。需要停用时，可以在同一位置清除密钥，并在阿里云 RAM 控制台中禁用或删除对应 AccessKey。

### 5. 发起云识别

1. 勾选一个或多个包含发票 PDF 的条目。
2. 点击批量工具条中的「云识别」。
3. 查看将调用的页数、跳过项和计费提示。
4. 确认后开始识别。
5. 在完成摘要中查看已补齐、待确认和失败的条目。

也可以在「识别提醒」视图使用批量建议，或在单个条目详情中点击「识别此发票」。

多页 PDF 会逐页调用并按页序合并。已有 XML 数据的条目会默认跳过；已有完整云识别结果的条目也会默认跳过，可以在确认页面中选择重新识别。

### 6. 计费和调用量

阿里云 OCR 按成功调用量计费，多页发票按实际调用页数计算。阿里云官网渠道通常按“免费额度、专用资源包、共享资源包、按量后付费”的顺序抵扣，具体额度和价格以阿里云当前页面为准。

- [OCR 产品计费说明](https://help.aliyun.com/zh/ocr/product-overview/product-billing/)
- [OCR 资源包说明](https://help.aliyun.com/zh/ocr/product-overview/resource-plans)
- [OCR 计费常见问题](https://help.aliyun.com/zh/ocr/support/billing-faq)

可以在 OCR 控制台查看调用量、资源包余量和账单。建议根据使用量设置余额或资源包告警。

### 7. 常见错误

- 提示组件缺失或损坏：在「软件与组件」中重新安装 OCR 识别组件。
- 提示密钥错误：重新核对 AccessKey ID 和 Secret，Secret 区分大小写。
- 提示无权限：确认 AccessKey 属于已授权 `AliyunOCRFullAccess` 的 RAM 用户。
- 提示服务未开通：回到 OCR 产品页开通增值税发票识别服务。
- 条目被跳过：检查条目是否包含发票 PDF，以及确认页面中的“跳过已有结果”选项。
- 结果需要确认：打开条目详情，在「阿里云识别」区域比较本地值和云端值。

## 十、设置、数据和更新

### 报账人和代填模式

在「设置 → 报账人」中管理姓名、审核人和默认报账人。

代填模式适合一台电脑整理多个人的材料。开启后，新建、批量导入和绑定包导入都可以选择报账人。

### 偏好

偏好中可以设置：

- 默认列表密度
- 浅色、深色或跟随系统的外观主题
- 卡片显示创建时间（默认关闭，精确到分钟）

首次使用可以保持默认值，熟悉流程后再按团队要求调整。

新建默认抬头、实付初值、付款截图识别方式、绑定包是否带出备注和标签属于报账方案设置，在「设置 → 报账方案 → 管理」里修改，设置页不再重复放置这些开关。方案修改不自动改写历史条目；主题、数据位置和网络更新偏好继续由本机设置控制。

### 抬头与税号

抬头目录属于报账方案。通用方案没有预填学校，BITFSAE 方案包含北京理工大学及教育基金会，其他团队维护自己的名称和税号。

在「设置 → 报账方案 → 管理」的「抬头」里增删抬头和税号，保存后生成新修订；新添加的抬头保存后才能选为新建默认抬头。识别和补材料仍按条目原修订核对；选择新建默认方案不会改变历史票面的购买方。

### 查验单设置

Tidoc 默认监测下载、桌面和文档目录中的新查验单。常用保存位置在其他目录时，可以设置一个额外归档目录。

「归档后清理原 PDF」开启后，查验单成功复制到条目时，原 PDF 会移到系统废纸篓或回收站。需要时可以从系统中恢复。

### 数据位置

「设置 → 数据位置」提供以下操作：

- 打开数据文件夹
- 打开导出目录
- 查看导出文件占用空间
- 清理拖拽中转文件和旧更新包
- 把数据迁移到新位置
- 恢复系统默认数据位置

数据迁移请使用软件中的迁移功能，让数据库和附件保持在同一数据目录中。

### 备份和恢复

备份步骤：

1. 退出 Tidoc。
2. 在「设置 → 数据位置」确认当前数据文件夹；也可以在退出前点击「打开文件夹」。
3. 复制整个数据文件夹到备份位置。

恢复步骤：

1. 退出 Tidoc。
2. 把当前数据文件夹移到另一个位置保留。
3. 把完整备份复制到原数据文件夹路径。
4. 启动 Tidoc，检查报账人、条目和附件。

数据库、附件、导出文件和组件目录应作为一个整体管理。软件中的数据迁移功能用于移动当前正在使用的数据目录，目标位置需要是空文件夹。

### 软件和组件更新

打开「设置 → 组件与更新 → 软件与组件 → 管理」，可以查看：

- Tidoc 核心版本
- 打印导出组件版本和完整性
- OCR 识别组件版本和完整性

Tidoc 默认在启动完成后检查版本，持续运行时也会按到期时间继续检查，每小时最多联网一次，可在此处关闭。发现核心新版本后，设置旁会出现下载按钮；点击后立即原位显示 0%，下载和校验完成后按钮变为重启。再次点击，旧版本会退出并自动打开新版本；首次启动会显示升级前后版本和本次变化，不出现首次安装向导。安装位置不支持原位替换时，更新页会保留 EXE / DMG 安装包入口。

打印和 OCR 组件会直接安装到本机数据目录，安装完成后状态会立即刷新。自动检查不会自动下载或安装，所有写入动作仍由用户点击触发。

## 十二、常见问题

### XML 没有进入批量导入预览

批量入口将能识别发票号码的独立 XML 放入导入组。仍未进入预览时，检查是否为受支持的发票 XML、文件是否损坏，以及本次是否已有同一发票。可以从单条「新建」核对具体错误；需要打印票面的输出还需补充 PDF。

### 付款截图没有自动绑定

常见原因包括截图金额识别为空、多个条目金额相同，或截图中出现多个付款数字。点击对应卡片的「付款」添加截图，或在系统提示中手动选择条目。

### 查验单没有自动归档

依次检查：

1. 查验单是否通过官网「打印」另存为 PDF。
2. 文件是否保存在下载、桌面、文档或设置的额外归档目录。
3. PDF 中是否包含可识别的发票号码。
4. 当前条目是否仍在等待本次查验。

也可以在卡片或详情中手动上传查验单。

### 软件升级后想重新处理旧发票

进入「识别提醒」或其他列表，选中条目并点击「重新识别」。软件会使用当前规则处理需要更新的文件。

### 打印按钮提示组件未安装

按弹窗提示安装，或打开「设置 → 组件与更新 → 软件与组件 → 管理」，安装打印导出组件。

### Word 中缺少姓名或银行卡信息

打开报账方案的「收款信息」，核对选定对象及必要字段。按人收款时检查映射，统一收款时检查本次选择。无收款段落的文档不需要银行信息。

### 导入绑定包时出现重复发票

重复发票会在预览中显示为「补充」或「无变化」。「补充」会把本机缺少的材料和信息合并到原条目，不覆盖本机非空内容；「无变化」表示现有条目已经包含包内内容，会安全跳过。

### 删除批次后条目还在

批次用于组织条目。「删除批次」默认保留条目，条目会回到「未进批次」；如需一起清理，可勾选「同时永久删除条目和全部附件」，确认后无法恢复。

### 从文件管理器双击 `.tidoc` 后图标没有刷新

先确认已经安装当前版本 Tidoc。Windows 可以注销并重新登录，或重启资源管理器；macOS 可以重新打开 Finder。系统更新文件关联缓存后会显示新图标。

## 十三、数据、网络和安全说明

这一节用于说明软件运行方式，日常使用可以按需查阅。

### 本机数据

Tidoc 的数据库、附件和设置保存在本机数据目录。主界面通过本地桌面窗口运行，日常整理无需启动浏览器服务。

删除条目时，对应附件会一起删除。删除批次默认只改变组织方式；只有在确认弹窗中明确选择同时删除条目，才会删除条目和附件。标签或筛选条件始终只改变组织方式。

### 网络访问

以下操作会使用网络：

- 打开国家税务总局查验平台
- 发起阿里云 OCR 识别
- 打开官网、GitHub、视频说明等外部链接
- 检查、下载或安装软件和组件更新

更新联网方式见[软件和组件更新](#软件和组件更新)。自动检查开启时会按设置检查版本；下载和安装仍由用户触发。团队适配包从本地导入，不新增后台下载团队规则的行为。

### AccessKey

阿里云 AccessKey 保存在本机数据中，导出的 `.tidoc` 绑定包不会携带密钥。绑定包导入后使用接收方电脑上的 OCR 配置。

建议为 Tidoc 使用独立 RAM 用户和独立 AccessKey。更换电脑或停止使用时，可在阿里云 RAM 控制台禁用旧 AccessKey。

### 绑定包完整性

`.tidoc` 绑定包带有 HMAC 完整性校验，用于发现文件在传输后的缺失或改动。绑定包中的发票、付款截图和个人信息仍是可读取的业务材料，传输和保存时应使用团队认可的安全方式。

### 识别数据

阿里云原始响应、解析结果、待确认状态和采用记录会保存在条目中，并随绑定包迁移。查看已经保存的结果不会产生新的 OCR 调用；重新发起识别会形成新的调用。

## 十四、报账方案

报账方案定义单位抬头、材料要求和输出格式。首次使用时，在设置中的「报账方案」选择适用方案。方案名称和修订会显示在方案设置中。

团队管理员可从开发手册取得 `.tidoc-preset` 文件。将文件单独拖入 Tidoc，检查包名和校验诊断，再选择安装为新方案或更新已有方案。安装后的方案保存在本机数据目录。选择默认方案只影响新建条目；已有条目继续使用创建时绑定的规则修订。

方案包不包含个人姓名、收款账号、条目或导出历史。接收方案后，应在本机补充收款对象和团队要求的字段。方案包含的 Word 或 PDF 输出还需要安装打印导出组件。

开发者和团队维护者请参阅[适配包开发手册](adapters/README.md)。

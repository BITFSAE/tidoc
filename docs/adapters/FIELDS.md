# 字段与设置

附加字段定义在 `fields.json` 的 `fields` 数组中。字段必须声明稳定 ID、作用域、类型和标签。允许的作用域是 `scheme`、`payee`、`entry`、`batch` 和 `export`。字段类型及长度、数值范围、选项由 Schema 限制。

设置描述放在 `scheme.json` 的 `settings` 对象中。适配包只能修改注册表开放的设置。每个设置的类型、默认值、选项及可用作用域见[生成的注册表参考](REFERENCE.md)。

普通设置按核心默认值、包默认值、本地方案覆盖的顺序合成。注册表允许的输出设置可继续由批次和本次导出覆盖，固定值及核心不变量最后检查。固定设置使用 `fixed` 且必须 `editable: false`。可编辑设置必须提供 `default`。`fixed` 和 `default` 不能同时出现。

默认输出的缺省继承与显式空列表不同，具体优先级及本次选择规则见[输出说明](OUTPUTS.md#默认输出与本次选择)。

`presentation` 可设为 `visible`、`advanced` 或 `hidden`。隐藏字段若必填，必须能从默认值或其他明确入口获得值。固定设置是流程约束，不是访问控制。

扩展字段不代表新增数据库列。用户值按方案和字段定义保存，并带有修订及历史信息。公共适配包只定义字段，不应写入个人姓名、账号或历史值。

绑定包中的备注和标签默认按每条资料固定修订的 `transfer.include_notes`、`transfer.include_tags` 处理。混合方案不会套用应用当前默认方案；用户明确选择仍须满足对应修订的固定要求。扩展字段的 `transfer` 策略独立检查，`never` 同时移除值及全部历史，`ask` 需要明确选择。

抬头目录和材料要求属于方案修订，不是应用全局 `meta`。两个本地副本即使共享修订，也分别保存字段和收款映射。更换默认方案只影响新条目，旧条目通过明确的重绑定预览调整。

报账人是材料归属人，姓名必填，审核人的必填和显示策略由方案控制。收款对象独立保存姓名、人员编号、联系方式、账户类型、开户行和账号。`payee.personnel_number_label` 默认为“人员编号”，可设为“学号”或“工号”；BITFSAE 使用“学号”。这只改变界面名称，不改变字符串值或前导零。

`single` 按“本次选择 → 批次选择 → 方案默认”解析；`by_claimant` 只使用明确映射；`none` 不要求收款资料。来源按完整对象选择，缺项不会用另一人的字段补上。

上下文金额采用十进制字符串，缺失保留 `null`，零和负数有效。人员编号和账号使用字符串，保留前导零。当前模板目录和文件名变量共用 [`tidoc_print/context_fields.json`](../../tidoc_print/context_fields.json)，由轻量读取函数提供给核心与打印组件。

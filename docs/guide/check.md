# 核对识别结果

导入发票时，Tidoc 会读取发票上的内容，并把需要你核对的地方标出来。本页说明怎么按状态视图逐项处理，以及出现「识别提醒」后怎么办。

## 用状态视图分步处理

主界面工具条里的状态视图把条目分成几组：

- 「全部」：当前范围内的全部条目。
- 「待补材料」：还缺必需材料的条目。
- 「识别提醒」：发票读出的内容需要核对的条目。
- 「已识别」：已经保存阿里云 OCR 结果的条目。
- 「OCR 待确认」：本地结果与阿里云结果有差异、等待你确认的条目。
- 「已修改」：实付金额与发票金额不同的条目。
- 「齐备」：必需材料已补齐，且发票没有「严重问题」的条目。

「已识别」和「OCR 待确认」只在安装了 OCR 识别组件后出现，见[阿里云 OCR](/guide/aliyun-ocr)。

![状态视图和筛选工具条](/images/status-views.png)

建议的顺序：先看「待补材料」，补齐材料；再看「识别提醒」，核对发票内容；处理完的条目会出现在「齐备」。卡片上的徽标会标出「识别提醒」，更严重的「严重问题」用更醒目的样式显示，鼠标停在徽标上可以看到原因。

## Tidoc 怎么读取发票

「识别」是把发票上的发票号码、日期、销售方、购买方、价税合计和物品明细读出来，填进条目。读取在本机完成，不需要联网。

- 发票有 XML 时，优先读取 XML 里的数据。同时有 PDF 时，还会核对两份文件的发票号码、日期、购销双方名称与税号、价税合计；结果不一致时保留 XML 的值，并提示你核对。PDF 无法读取时也会提醒。
- 没有 XML 时，读取 PDF 里的文字。电子发票 PDF 带有文字，可以读出；图片类的扫描件没有文字，读不出。常见数电发票里的分栏明细、免税与不征税行、折扣行和错位文字，会在读取时整理。同品名折扣会合并到对应商品，数量保留商品原值，金额显示折后金额。长品名与规格交错、单位分到下一行时，还会按票面位置补充读取；名称里的尺寸星号会保留。
- 读不到的字段留空，由你在详情里补上。发票号码或销售方读不到时，卡片上分别显示「无发票号」「未识别销售方」。

## 出现识别提醒时怎么办

以下情况会出现「识别提醒」：

- 没有读到物品明细。
- 明细金额的合计与价税合计不一致，可能是明细没读全，以发票上的价税合计为准。
- 没有读到购买方抬头，或抬头不在方案已配置的抬头里。
- 方案为该抬头配置了税号，但购买方税号没有读到，或与抬头不一致。
- 「不含税金额合计」加「税额合计」不等于价税合计，或大写金额折算后与价税合计不一致。通常是某个数字读错了，请对照发票原件修改总额或明细。
- 没有在票面上找到「价税合计」，只能暂用页面上最大的金额作为总额，提醒里会写明可信度低。
- 同一张发票用两种方式读取文字，发票号码、开票日期、购销双方名称或税号、价税合计的结果不同。提醒会写出两个值和软件采用的那个，请与发票原件核对。
- 18 位统一社会信用代码的校验位不符，或开票日期不是有效日期，多半是识别有误。个人抬头和旧版税号不做这项检查。
- 税额与不含税金额的比例超出票面税率的范围。这条只作参考：逐行四舍五入、折扣和免税都会让两者略有出入，不要求税额恰好等于金额乘税率。
- 开启了付款截图金额识别后，截图没有读出金额，或截图合计与发票金额不一致。

以上提醒在导入或点「重新识别」时产生。升级软件前已有的条目，需要重新识别才会出现新增的提醒，方法见下文。修改总额或采用阿里云结果后，软件仍会用原发票中的金额和字段核对依据检查当前值，相关提示不会仅因重算而丢失；重新识别会按当前材料刷新这些提示。

处理步骤：

1. 点击「识别提醒」视图，或把鼠标停在卡片的「识别提醒」徽标上查看原因。
2. 点击卡片打开详情，「关键信息」下方显示具体的提醒内容。
3. 对照发票原件核对。需要修改时，点击「关键信息」里的数值直接编辑，改完按回车；「物品明细」里点击单元格编辑，「＋ 添加明细行」补充漏掉的行。

![带识别提醒的条目详情](/images/warning-detail.png)

修改会记在详情底部的「修改记录」里。识别提醒只提示发票内容需要核对，不影响材料齐备。「严重问题」会使条目不算齐备，例如发票上的抬头与条目所选抬头不一致。

## 重新识别

软件升级后识别方法有改进，或者替换了发票、付款截图以后，可以刷新识别结果：

发票识别方法更新后，列表上方会提示当前列表中可重新识别的发票数量。点击「重新识别发票」，再点击「开始识别」。这一步只在本机处理发票，不会再次调用云识别。处理成功的发票不再计入提醒，失败的发票可以重试。

暂时不处理时，点击「关闭提醒」。同一次识别方法更新不再提示；下次识别方法更新后会再次提醒。关闭提醒后，仍可按下面的方法手动重新识别。

1. 选中一个或多个条目。多选方法见[筛选、标签与批次](/guide/organize)。
2. 点击批量工具条里的「重新识别」。
3. 在「重新识别」窗口勾选「发票」「付款截图」，窗口显示各自待识别和已处理的数量。付款截图金额识别关闭时，「付款截图」不能勾选。
4. 点击「开始识别」，完成后查看处理结果。

已经按当前方法处理过、内容也没有变化的文件会跳过。升级软件后想更新旧发票，可以在「识别提醒」视图里全选条目，再点「重新识别」。

如果「OCR 待确认」里的差异涉及品名换行、跨页或单位和数量缺失，也可以先重新识别发票，再查看比对结果。这一步使用本机的发票文件和已保存的阿里云结果，不会发起新的云识别。两种结果都可能有遗漏，仍需对照原件核对。

## 对比阿里云的识别结果

阿里云 OCR 是可选的付费功能。使用「云识别」后，详情里的「阿里云识别」把「当前值」和「阿里云值」并排列出：

- 本地字段为空时，部分字段会自动补齐。
- 明细有差异时，条目进入「OCR 待确认」。
- 每个字段可以点「采用」，也可以保留当前值；明细有差异时可以点「采用阿里云明细」。

软件会在本机按当前识别方法整理已保存的阿里云原文，例如把跨页拆开的品名和对应折扣接回同一商品。查看和采用这些结果不会新增云调用，原始识别记录与调用次数保留。仍有差异时，请先对照发票 PDF，再决定是否采用。

开通服务、配置密钥和计费说明见[阿里云 OCR](/guide/aliyun-ocr)。

## 遇到识别有问题的发票

发票版式很多，如果遇到本地识别不准、金额有偏差或明细漏项的发票：

- 欢迎把脱敏后的发票文件（PDF 或 XML，隐去个人隐私信息）发送到邮箱 `info@bitfsae.com`，我们会加入测试集持续改进。
- 也可以在 [GitHub Issues](https://github.com/BITFSAE/tidoc/issues) 提交反馈并附上现象说明。
